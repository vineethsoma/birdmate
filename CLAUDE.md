# CLAUDE.md

Project rules live in [`AGENTS.md`](./AGENTS.md) (the Birdmate constitution, generated by APM; do not edit it by hand,
change `.apm/` primitives instead). Read it first.

## Formal verification

- `formal/` is the **read-only source of truth**: `ontology.ts` (what exists, from the eBird CSV) and
  `invariants.ts` (what must always be true). Never edit it, and never weaken a test or verifier to get green.
  If an invariant looks wrong, say so in the PR description; maintainers approve spec changes (CODEOWNERS).
- Verification runs automatically via Claude Code hooks (`.claude/settings.json`):
  edits to `formal/` and `.claude/hooks` are blocked; after each edit `verify:fast` gives feedback;
  you cannot finish a turn while `verify:all` fails (3 retries, then CI is the backstop).
- Run by hand from `backend/`: `npm run verify:fast` (types + contract), `npm run verify:all -- --runs 1000`.
  Individual steps: `verify:types`, `verify:data`, `verify:contract`, `verify:pbt`.
- A failure prints the violated invariant and a shrunk counterexample. Fix `backend/` or `frontend/`.
  The read-only `verifier` subagent (`.claude/agents/verifier.md`) can map a counterexample to code.

## Commands

- Unit tests: `cd backend && npm test` (some integration tests need `OPENAI_API_KEY` and network), `cd frontend && npm test`
- Verification never touches `backend/database/*.db` (it works on a temp copy); if tests dirty the tracked
  SQLite files, `git checkout -- backend/database`.
